# 法务对话助手

本文面向需要在法律工作台中进行资料检索和法务问答的使用者，也面向负责权限和数据生命周期的工作区管理员。入口是 `/platform/legal-assistant`；它是法律工作台中的对话功能，不是合同审查结果页，也不是完整的案件或合同项目管理系统。

## 快速结论

| 项目 | 当前状态 |
| --- | --- |
| 工作台入口 | 已实现；左侧“法律工作台”下的“法务助手” |
| 多轮对话 | 已实现；复用现有 Agent 对话、SSE、消息历史和引用展示 |
| 知识库与附件 | 已实现；复用现有知识库选择和临时会话附件，不复制知识库数据 |
| 默认 Agent | 已实现；`builtin-legal-assistant`，强调法规/案例/合规/合同问题的证据优先、事实与建议分离及不确定性披露 |
| 普通对话记忆 | 已实现；法务助手的 Agent、知识库、文件、标签和模型选择单独保存 |
| 租户开关 | 已实现；关闭后入口隐藏，法务路由、法务会话读取/问答/附件访问由后端拒绝 |
| 案件/合同项目管理 | 未实现；本功能不迁移 LexAI 的法律项目、合同起草和案件管理 |

## 使用方式

1. 确认当前工作区已启用法律工作台。
2. 从左侧进入“法律工作台” → “法务助手”。
3. 在输入栏选择已有知识库、文件或临时附件；需要外部资料时显式打开网页检索。
4. 提问后等待流式回答，并展开引用、附件或生成的产物检查原始依据。
5. 离开法务助手后，普通知识库对话的输入栏选择恢复到进入前状态。

法务助手会尽量区分“资料中明确写出的事实”“基于资料的分析”和“需要律师或人工确认的建议”。如果没有足够依据，回答应明确说明缺少的事实或来源，不应把模型推测当作法律结论。输出不能替代执业律师意见、正式法律审查或当地法律要求下的专业服务。

## 会话归属与访问边界

创建法务会话使用 `POST /api/v1/legal-assistant/sessions`，服务端固定写入 `workspace_mode=legal_assistant`。普通 `POST /api/v1/sessions` 创建的会话固定为 `workspace_mode=platform`；客户端不能通过更新会话元数据改变归属。

这个归属用于两项保护：

- 关闭法律工作台时，法务会话不会出现在普通会话列表中，法务会话的消息、问答流、临时文档、产物和终端访问也会被服务端拒绝；普通平台会话不受影响。
- Owner 执行法律工作台数据删除时，只清理合同审查数据和 `workspace_mode=legal_assistant` 的会话级数据。共享资源仍被其他对象引用时保留；外部存储清理失败会返回错误，便于重试。

前端隐藏入口只是体验层，不能代替后端鉴权。工作区开关保存失败时，服务端的 `403` 仍是最终行为。

## API 与验证

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/v1/legal-assistant/sessions` | 创建法务助手会话 |
| `POST` | `/api/v1/agent-chat/:session_id` | 复用现有 Agent 流式问答；会话必须属于当前工作区和当前用户 |
| `POST` | `/api/v1/knowledge-chat/:session_id` | 在选择知识库时复用现有知识问答 |
| `GET` | `/api/v1/messages/:session_id/load` | 加载法务会话消息；受工作区开关和会话归属保护 |
| `DELETE` | `/api/v1/legal-workspace-data` | Owner 清理法律工作台数据，包含法务助手会话级数据 |

实现验证应至少包括：关闭开关后法务入口和后端访问均不可用；普通会话仍可读写；跨用户或跨租户法务会话返回未找到/拒绝；Owner 清理不删除普通平台会话；重新开启后未删除的法务数据可继续访问；前端 `npm run type-check`、`npm run check-i18n` 和后端相关测试通过。

## 非目标与已知限制

- 不提供 LexAI 的法律项目、案件管理、合同起草、版本对比或红线编辑。
- 默认 Agent 不是法律意见保证；法规时效、司法辖区和事实完整性仍需人工核验。
- “删除工作台数据”会清理数据库中的法务会话归属及关联会话级记录；共享知识库、共享 Agent 和仍被其他对象引用的资源不属于该删除范围。
