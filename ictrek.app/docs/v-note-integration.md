# V-Note 与 HybRAG 联动设计

状态：身份、私有知识库、个人设置与页面打开期间的手动导入已有源码；自动同步、撤销和删除对账待实现，尚未发布。日期：2026-11-11。

本设计记录用户已经确定的交互边界，以及委托开发者决定的默认行为。第 1～12 节描述目标行为，实施范围以第 13～15 节为准，不能当作已发布功能。既有同步快照取点修复不代表联动已经实现。

## 1. 用户如何使用

唯一设置入口为 **V-Note → 个人中心 → 集成 → HybRAG**。HybRAG 展示来源、进度和返回设置的链接，配置在 V-Note 修改。

页面由三部分组成：

| 区域 | 内容 |
| --- | --- |
| 连接 | 当前 VOS 用户、HybRAG 服务状态、联动总开关、异常与重试 |
| 自动同步 | 间隔 / 夜间 / 仅手动；时间设置；下次执行时间；排队数量 |
| 笔记本 | 树形选择、根笔记本对应的知识库、子树暂停标记、同步状态与操作 |

首次打开设置时自动发现同一 VOS 中的 HybRAG，并尝试识别同一个当前用户。不要求复制 Token 或单独点击“连接”。首次联动总开关为关闭；自动识别身份不等于允许读取正文。选择同步范围并开启后才导入笔记。

未安装时显示“未安装 HybRAG”；未启动显示“服务暂不可用”；身份无法核对显示“无法确认当前账号”；模型或存储未配置显示“需要在 HybRAG 完成模型或存储设置”，附跳转入口。以上状态均不阻断写笔记。

选择器可读取当前用户的笔记本名称与层级，不提前读取未选择笔记本的正文。开启前显示选中根笔记本、将创建的知识库和可用的导入数量；数量通过索引或缓存统计取得，不对每页重新计数。

可多选根笔记本批量开启、暂停、恢复、立即同步或删除对应知识库。批量操作逐项展示结果，失败项目可重试，成功项目不回滚。

## 2. 笔记本与知识库的对应

每个选中的根笔记本创建一个 HybRAG 托管知识库，默认名为 `V-Note / 笔记本路径`，包含其全部子笔记本。这里的“根”指用户选定的同步根节点，不必是笔记本树的顶层。

- 父节点已经选中时，子节点不重复建立知识库；可对任意子树暂停。
- 新增子笔记本自动纳入，遵守祖先的暂停状态。
- 首版只提供笔记本 / 子树级暂停，不提供单篇笔记暂停。
- 已建立两个独立知识库后再选择共同祖先，不静默合并、删除知识库。界面要求先停止重叠的子根同步，保留其副本，再将祖先作为新同步根；操作前说明新库会包含重复副本。
- 名称和位置变化更新显示信息；根节点的稳定 ID 决定映射，不用名称判断是否已建库。
- 根节点自身被移动时保留映射；笔记移出一个同步根时移除其来源文档，移入另一个同步根时在新库导入。跨库移动不是一次事务，显示处理中，不承诺瞬时切换。
- 根笔记本在 V-Note 被删除时停止该根同步并移除其来源文档，保留空知识库与记录供用户检查；不自动删除整个知识库。

托管知识库正文由 V-Note 维护，在 HybRAG 只读；不允许上传普通文档混入或直接改写同步正文。用户在 HybRAG 仍可调整允许的检索与处理选项。首版不支持回写 V-Note。

## 3. 各种“停止”的区别

| 操作 | 后续更新 | 已同步内容 | 实时读取 | 恢复方式 |
| --- | --- | --- | --- | --- |
| 暂停根或子树 | 不处理该范围的新增与修改 | 保留，仍可检索，标明暂停及最后同步时间 | 该范围不实时读取 | 恢复后补齐当前状态 |
| 停止一个根的同步 | 停止该根更新，收回其读取范围 | 保留对应知识库，标明已停止 | 禁止 | 重新开启，复用原映射并核对差异 |
| 关闭整个联动 | 停止调度，撤销连接专用凭据 | 保留全部已有知识库 | 禁止 | 重新开启后自动核验身份和授权 |
| 删除同步知识库 | 先停止对应根并取消任务 | 删除该托管知识库及其文档 / 索引 | 禁止 | 后续明确重新开启时建新库 |

暂停用于控制计算负载，不是隐藏内容或撤销历史访问。暂停时源笔记真的被删除或移出授权范围，仍执行相应移除，不把已删除内容长期冻结在副本中。

删除知识库前必须列出库名和文档数量并二次确认；批量删除同样逐项列出。只允许操作映射记录明确指向的、当前用户拥有的托管知识库，不按名称匹配删除；不删除 V-Note 原始笔记。清除失败显示“清理中 / 清理失败”，不可误报已删除。

从 HybRAG 删除托管知识库也必须结束对应根的同步映射，不能下次轮询自动建回来。停止或删除后重新登录、发现服务、升级应用，都不能自动重新开启联动。

“立即同步”跳过时间安排和编辑等待，仍受单并发、身份与范围限制。暂停项目先恢复，停止项目先开启，避免一次按钮意外改变长期状态。

## 4. 自动同步策略

策略对当前用户的全部根统一生效，暂停状态按根 / 子树保存。默认 **间隔 15 分钟**，可选 5 / 15 / 30 / 60 分钟；不根据 CPU 架构推断设备性能。tc207 可主动改为夜间模式。

| 模式 | 自动行为 | 首次导入 |
| --- | --- | --- |
| 间隔 | 到期获取变更并调度已稳定的笔记 | 保存范围并开启后开始排队 |
| 夜间 | 在指定窗口获取变更、分批索引 | 等待窗口，可手动提前 |
| 仅手动 | 不自动拉取正文或建立索引 | 点击立即同步才开始 |

夜间默认窗口为 02:00–06:00，时区初始取设置者的浏览器 IANA 时区并存到服务端，页面可修改且显示具体时区及下次执行时间。支持跨午夜；夏令时按当地实际时刻执行，不补跑重复窗口。浏览器关闭后服务端继续调度；设备关闭时不承诺定时唤醒，重启后等下一个窗口，窗口内重启则续跑。

窗口结束后不领取新的索引任务，当前笔记完成后停止；失败重试若超出窗口则等下一窗口。一次超大笔记可能超过窗口，界面明确提示。时间策略限制新索引任务开始时间，不强杀运行中的解析或模型请求。

普通自动任务在笔记停止修改 2 分钟后才索引。连续保存按笔记 ID 合并为最新版本；达到下次允许执行时刻才开始。点击立即同步可跳过等待，但执行中若再次编辑，完成后仍会按最新版本补跑。

V-Note 在源删除、范围收缩、停止授权时写入轻量持久控制事件，健康连接时尽快通知 HybRAG 隐藏或移除相应来源；这些操作不等待夜间窗口，也不调用解析模型。仅手动模式仍处理这类控制事件。断网期间不能保证立即移除，必须显示待确认，并在连接恢复后优先执行。

## 5. 文件格式与计算成本

每篇普通文本笔记生成一份 UTF-8 Markdown，内部文件名使用稳定笔记 ID，如 `memo_<id>.md`；正文格式为标题加内容：

```markdown
# 项目记录

这里是 V-Note 中的正文……
```

笔记标题、笔记本路径、来源 ID、原文跳转信息、源版本和时间另外保存为元数据。更新时间、同步时间等易变字段不写入 Markdown 正文，避免制造内容变化。笔记本路径作为导航元数据维护，调整路径不应为了目录展示而重新向量化。

计算与保存规范化后的最终 Markdown 指纹，不能只依赖 `updated_at` 或 V-Note 的编辑器 JSON 哈希。标签、排序、置顶、笔记本名称改变只更新元数据；标题改变会改变 Markdown，因此首版会重新索引该篇笔记。

| 变化 | 解析与模型行为 |
| --- | --- |
| 没有源变更 | 仅变更游标查询，不解析、不调用模型 |
| 有事件但最终 Markdown 相同 | 更新来源元数据，跳过解析和 embedding |
| 正文或标题改变 | 只重建该篇笔记的切分和索引，可能重新调用所有文本块的 embedding |
| 源笔记删除或移出范围 | 移除对应来源文档与索引，不重新解析 |

首版不承诺块级差分索引或跨版本 embedding 缓存。一篇很长的笔记只改一处，整篇仍可能重新向量化。

默认处理配置：Markdown 文本解析、切分、全文和向量检索；关闭摘要、问题生成、图谱、图片理解、自动 Wiki 和自动标签等额外后台 LLM 任务。必须在最终处理配置中显式关闭，不能以“未指定模型”替代开关。用户以后在 HybRAG 开启额外处理时，应提示新增计算负载。

现有知识库编辑界面要求摘要模型，而文档处理覆盖配置已有关闭摘要的能力；新增托管知识库创建路径必须协调界面、后端校验和处理配置。缺少 embedding 或存储时可以保留连接与范围草稿，显示待配置，不创建看似可用却无法索引的知识库，也不静默切换云模型。

首版完整支持普通文本笔记。附件二进制、图片 OCR、PDF、音视频、图表、海报、信息图及多维表格的专用格式不自动展开解析；界面按类型列出跳过数量与原因，不把原始 JSON 或模板源码当正文导入。普通正文可保留附件引用的可读说明，不创建无需登录的附件链接。支持这些类型前分别设计导出与变更跟踪。

## 6. tc207 的队列限制

同步轮询、获取内容、解析、向量化分别计时计数。限制必须覆盖真正消耗资源的下游任务；仅让数据源 Fetch 串行，不能保证后续解析也串行。

- 所有用户和所有根共享一个 V-Note 后台文档处理槽位，默认最多 1 篇进入解析 / 向量化流程；通过持久租约和任务版本校验避免多个服务副本各跑一篇。
- 分页拉取并限制待处理内容缓冲，不把整个用户笔记空间留在内存。
- 手动同步优先于同一集成的自动任务；不同根轮转，失败项目退避，不阻塞其他根。
- 已排队的同篇版本合并，不积累每次自动保存的所有历史任务。
- 前台问答优先原则需要模型调度器实际支持才能生效；不能仅凭队列名声称能抢占 GPU。模型请求执行期间不强制打断，到可检查的任务边界再让出。
- 单并发只约束本联动，不保证其他应用不占 GPU，也不保证模型一定装得进显存。模型 OOM 或不可用时退避并显示错误，不无限快速重试。

首次大量导入显示“等待 / 已获取 / 已索引 / 失败 / 跳过”数量；不从笔记数量猜测完成时间。tc207 的吞吐与显存预算以实际笔记长度、切分配置和模型实测为准。

## 7. 身份与授权

自动识别必须由后端分别验证同一平台、同一个 VOS 稳定用户 subject。用户名、邮箱、前端传入的 user_id、管理员权限和当前选中的工作区都不能代替这个绑定。

HybRAG 需要新增持久化的平台用户绑定及明确的个人空间归属；不能只使用现有 `${username}@local` 匹配，也不能把上次登录的活动工作区当作个人空间。用户名变化后仍绑定同一账号，绑定冲突时停止并提示，不自动合并账号或迁移数据。

自动握手在首次打开 V-Note 集成设置或开启联动时利用已验证的当前 VOS 登录完成。若目标 VOS 无法让两个应用核对同一 subject，则显示身份无法关联并停止，不用管理员凭据兜底。

后台使用绑定用户、平台实例、连接 ID 和允许资源的专用可撤销委托，不能长期保存短期 VOS access token，也不能用工作区级 API Key。凭据加密保存，响应及日志不回传明文；不用普通全空间 MCP Token 作为范围隔离措施。VOS 应用 context 中的永久 admin access-token 只代表服务，不能作为当前用户授权的证明；两个应用各自的应用 access token 也不能未经验证直接跨应用通用，必须验证受控交换或委托路径。

源端每次读取按当前根选择和暂停状态检查范围；目标端每次入队、执行、检索检查用户、空间和连接版本。缩小范围后已经在队列中的旧任务不能再次发布已移除内容。

关闭联动先本地阻断执行与实时查询，再执行双边撤销。服务不可用时保留撤销待办，恢复后完成；此期间不因为自动发现而重新授权。

用户停用、绑定丢失、空间归属变化、知识库被共享或管理员改变访问策略时暂停联动并拒绝新增读取。托管知识库需禁止共享、公开和跨空间复制授权；所有检索、引用、导出和工具路径均验证所有者，不能只隐藏界面按钮。管理员常规管理权限与联动授权分开，连接身份不能携带跨用户管理能力。

现有两个应用均不具备完整的 VOS 停用传播闭环；本地会话或普通 API Token 仍有效不能证明平台用户仍启用。专用委托必须检查所属用户当前状态，并与平台停用 / 撤销机制关联；平台接口是否支持可靠状态检查和传播需验证。该能力不成立时不得把连接标记为可持续后台授权；不能只等用户下一次登录才处理停用。

## 8. 服务职责与协议

V-Note 保存用户选择、全局策略、根和暂停子树、配置版本、控制事件及操作记录；它是配置的唯一来源。HybRAG 保存知识库映射、变更游标、待处理版本、索引进度、错误及执行队列；它负责调度和模型工作。

同一 VOS 服务端通过已有 `v-note-backend:8787` 和 `hybrag-app:8080` 别名发现。它们是容器内访问地址；用户跳转使用 VOS 的应用路径，不把 Docker 域名发给浏览器。服务端地址来自受控配置，不接受浏览器提供任意目标 URL；委托不能跟随重定向泄露到其他站点。

新增版本化能力握手和集成专用接口，契约至少覆盖：身份绑定、配置快照和版本、授权范围、受限笔记本树、分页快照、变更读取、来源读取 / 搜索、状态上报、停止、撤销及删除确认。具体路由沿用两个应用的命名约定，不把本设计中的概念名当作已经存在的 API。

两个应用升级不同步时先协商协议版本与能力。不兼容显示需升级，不静默改成全量扫描、共享凭据或人工 Token。

配置更新使用版本检查；跨应用写入通过持久待办和幂等键重试。重复点击或超时重发不能重复建库、重复创建委托或把旧配置覆盖新配置。浏览器关闭不影响服务端调度；服务端重启从持久状态恢复。

## 9. 首次导入、增量及恢复

复用 V-Note 的变更日志思想，新增集成专用的受限读取边界：现有 `/sync/bootstrap` 和 `/sync/changes` 返回整个用户空间，不可直接暴露给只有部分笔记本权限的集成。

首次导入先记录变更游标和空间 identity，再按稳定 ID 分页读取授权范围；后续页不反复加载全空间目录或做 COUNT。保留第一页游标，完成快照后从该游标回放，合并读取期间发生的变更。范围过滤必须在服务端查询 / 返回前执行，不能先把全空间正文拉到 HybRAG 再筛选。

根 / 子树移动会改变旧笔记是否在范围内，不能只处理笔记事件。目录变动后重算范围并对受影响的子树做有界补偿遍历；已有来源 ID 清单负责对照移除。同步账本记录稳定节点 ID、父节点与已见版本，支持暂停期间保留当前可查询副本、恢复后收敛。

进度至少区分 **已读取游标** 与 **已完成索引版本**。事件和待处理最新版本可靠落盘后才能推进读取游标；解析请求仅入队不代表索引成功。每篇完成前核对源版本、配置版本、暂停与撤销标记，过期工作不能覆盖新版本。

每个来源以 `(连接 ID, 根 ID, 笔记 ID)` 关联知识库文档；同一篇更新保留知识文档 ID。崩溃和超时至少一次重试，通过幂等约束收敛，不承诺跨应用恰好一次执行。

源 identity 变化、日志缺口、游标倒退时先标记需要重建，对选定范围重新取得快照。只有快照完整成功后才核对移除旧来源，部分读取失败不能被当作源删除。授权范围收缩等明确控制事件仍立即生效。

现有文件替换会清理旧索引后重建，首版允许该篇笔记短暂不可检索；失败标为同步失败，不宣称旧索引仍完整可用。实时查询可在未暂停且仍获授权时补充内容。后台错误按来源区分权限、模型、存储、内容类型和服务可用性。

## 10. 问答、来源与状态

个人普通聊天默认可使用已同步且仍属于当前用户的知识库。用户主动指定其他知识库时尊重该范围；不强行把所有 V-Note 内容加入每个问题。个人 Agent 的工具策略决定是否发起受限实时搜索。

实时查询仅访问当前开启、选中、未暂停的范围，不建索引；文本搜索和读取本身不额外向量化笔记，但后续回答仍可能调用聊天模型。夜间 / 仅手动策略不阻止按问题需要实时读取。共享 Agent、共享会话、公开 API / 发布渠道不能自动获得此权限。

来源展示笔记标题、笔记本、已索引或实时、源更新时间、索引时间及“在 V-Note 打开”。跳转必须仍经过 VOS 当前用户鉴权，不能使用公开分享链接。暂停或停止副本显示“内容可能已过期”；已暂停范围不走实时读取。

连接状态、自动策略和处理进度分别显示，避免把“已连接”误认为“已经全部索引”。根级进度包含等待时间窗口、编辑稳定等待、排队、同步中、已完成、部分失败、暂停、已停止；错误提供原因和可执行的重试或设置入口。

## 14. 私有知识库与手动单篇同步实施记录

### 本阶段入口与范围

V-Note 已登录用户调用 `POST /api/v1/integrations/hybrag/sync-note`，JSON 包含
`accessToken`（新取得的当前 VOS 用户令牌）、`rootId`、`memoId`。此接口是后端基础，
尚无个人中心按钮或自动读取前端 VOS 令牌的流程，不能宣称已实现无感连接。

源端核对会话与稳定 subject，按个人空间和根笔记本子树读取该篇笔记，生成五分钟单次票据，
仅存票据哈希、所有者、范围、标题与内容版本。HybRAG 的
`POST /api/v1/vnote/import-note` 校验新的 VOS 用户证明并解析已绑定的稳定账号，
再通过 V-Note `POST /api/integrations/hybrag/redeem` 兑换同一用户的票据。
兑换时原子复核身份、启用状态、个人空间成员关系、笔记位置与内容版本，防止移出范围或撤权后导出。
不同 subject、过期、重复兑换、源内容变更均拒绝；请求结束后源端删除票据。

目标库和文档 ID 由本地所有者、根 ID、笔记 ID 确定，重复请求不会建立副本。
KB 的 `private_owner_id` 和 `v_note_root_id` 创建后不可通过普通更新改写。
同空间成员、管理员、API / embed 主体、共享 Agent 均不能据空间权限读取这些库；
共享、克隆与移动被阻止。普通上传、编辑、删除、取消、重解析不得绕过专用同步入口。

### 文档表示与资源控制

笔记以 `# 标题\n\n正文\n` 组成逻辑 Markdown 文档，存入现有手工知识记录的数据库 metadata；
**不生成磁盘或对象存储 `.md` 原文件**，避免现有按空间鉴权的原文件链接暴露私人正文。
保留根、笔记、源更新时间、内容哈希、导入 attempt 等来源字段。附件、图片、内嵌资源及特殊类型笔记暂拒绝，
不转换为其他解析格式；V-Note 文档也不进入图片下载或存储解析器。

标题和正文相同且已有任务或解析已完成时直接返回现有状态，不再次调用 Embedding。
变化时更新同一文档并整篇重新切块、索引。摘要、问题、图谱、Wiki、自动标签和 KB 自动描述均不启用；
需事先配置启用的默认 Embedding 模型，不按名称猜模型或静默改用其他模型。

全 HybRAG 实例只有一个 V-Note 入库门闩，包含待处理、解析中和后处理，其他笔记返回
目标端 `409 vnote_busy` / 源端 `409 hybrag_busy`。提交短租约与下游文档状态分别控制提交和解析；
attempt 比对与数据库原子领取阻止旧任务、重复任务执行清理和向量化，旧提交不能覆盖新版本。
本阶段不自动排队重试，也没有持久后台委托。异常退出后若文档停在 processing，依赖已有卡住任务恢复，
不会仅因提交租约到期就并发启动下一篇；可观察的恢复状态与运维重试仍需后续完善。

## 17. 后台授权与控制重试

VOS 开发分支提供仅能核验自身主体状态的可撤销凭据。签发必须有明确同意、新的 RS256
人类用户证明以及当前用户和双方安装状态；平台不保存普通 OAuth access/refresh token。
PostgreSQL 持久撤销表统一登出、OAuth 撤销和签发使用的 JWT ID；签发与撤销使用同一事务锁，
升级切换前的旧证明不能签发后台授权。普通登出撤销登录证明，已提交的后台授权仍有独立生命周期。
平台最小迁移、重启后撤销读取及竞争控制已通过隔离 PostgreSQL 测试，尚未做真实平台升级。

V-Note 0100–0101 保存与精确用户、个人空间和 subject 绑定的加密凭据、签发预留及撤销待办。
个人空间必须由本人独占；成员身份、共享的个人空间或其他用户的凭据不能开启这条路径。
保存“启用同步”时通过 VOS 桥接静默取得新证明并申请授权；不另设连接按钮，不复制令牌。
目标不具备能力时保留原手动方式，已知失效的后台凭据不能退回普通证明。页面只轮询小型配置状态，
不反复扫描全空间目录。服务端每 30 秒有界投递控制及撤销消息，失败退避；账号/配置删除时保留停用记录。
撤销中的加密凭据必须保留到平台与目标确认后才删除；失效凭据仅可投递对应连接的停用控制，不能重新开启或读取状态。

HybRAG PostgreSQL 000164 / SQLite 000068 保存该连接的加密凭据。VOS 包会在原有持久
运行目录中自动生成独立的 0600 权限密钥，不改变登录、签名链接或模型密钥；升级必须保留运行存储。

## 19. 保留副本的当前用户核验

普通 HTTP 请求在原认证之后附加惰性的 V-Note 私有读取校验。只有真正访问 V-Note 知识库
时，才用本次用户证明重新核验 VOS 当前启用状态及既有稳定绑定；同一请求复用结果，
不同请求不缓存“用户有效”。单独持有旧 HybRAG JWT、服务令牌、无效证明或其他主体均不能
读取这些知识库。无人值守的 acting-via 身份也不能继承个人 Web 读取权限。

Web 端通过现有 VOS 桥接无感取得证明，仅在内存短时保留，附到本应用同源 API 和聊天 SSE；
不会发给其他域、其他应用或普通下载地址，也不新增宽权限刷新令牌存储。桥接或核验不可用时
私有读取关闭，普通知识库保持原认证路径。内部索引继续使用独立的后台授权与处理围栏。

副本读取不依赖“同步授权仍有效”：本人主动停止同步后，只要当前平台账号正常，仍可读取
保留副本。本节针对 V-Note 知识库读取，不改写已经返回的聊天内容或客户端缓存。
真实双端升级与平台停用交互验收仍未完成；当前代码未部署或发布。

## 20. 根暂停、编辑稳定等待与执行边界

V-Note 0105 保存选中根的暂停状态。个人中心根卡片可暂停或恢复，保存后生效；取消勾选根
则停止该根同步，两者都会保留已发布副本。暂停不撤销整个连接，源端拒绝该根的实时读取、
正文导出和手动推进；恢复必须送达新的配置版本，再完整对账。旧客户端省略暂停字段不会
清除仍选中的暂停。当前只支持整根暂停，单篇笔记及子树暂停尚未实现。

自动待办在最近编辑后等待约一分钟稳定期；再次改变标题或内容会顺延，相同版本不反复
延长等待。初次遍历的旧笔记可直接处理；异常或未来时间戳最多等待一分钟。“立即同步”
不走这段等待。等候及全局模型槽忙时不导出正文；15 分钟轮询不等于每轮重新解析。
夜间计划除调度端检查外，真实 worker 在开始前再次核验窗口，排队跨过窗口的未开始任务
会取消暂存；已经开始的单篇允许完成。

重复任务不能取消另一 worker 已领取的 processing 任务，旧 pending 快照也不能释放其槽位。
外部索引批次失败结果未知时立即写入仅限诊断字段的恢复提示；即使控制已撤销，也不丢失
该提示，但不能写入正文、标题、元数据或发布指针。停用同步后页面仍可显示本人的恢复告警。
未知结果保持全局槽位，不自动重试模型或宣称已安全恢复。私有读取证明在中间件取出后
从请求头移除，避免后续代理转发给其他服务。

根名称通过小型 plan 查询传递。后台连接的空根及仅手动计划也会创建对应私有知识库，
不遍历正文或启动模型；创建仍要求已有可用默认 embedding 配置。目录改名只更新知识库名称，
包括正文未变的手动导入。创建与改名在数据库事务中锁定并核对当前控制版本，迟到的停用前
请求不能创建或改名；已软删除的知识库不能由这条路径复活。托管知识库显式删除、重新启用
与物理索引清理的完整生命周期仍待补齐。

## 21. 未开始任务补投与无需模型的删除对账

自动队列中的精确 attempt 若持续 pending 超过 90 秒，按任务 ID 查询实际队列状态，最多每分钟
检查一次，不扫描整个任务队列。仍在等待、运行、计划或重试的任务保持原位，不绕过退避。
确认任务缺失时，使用数据库内同一份已授权 Markdown、同一任务 ID 和同一 attempt 补投；
已归档而数据库仍 pending 时恢复原任务。补投前重新核验本地控制、全局槽位、平台及源范围；
队列读取失败不能当作任务已丢失。Lite 无持久队列时也可补投未开始任务。

恢复不修改正文、处理状态或发布指针，不创建新物理版本、不另取源正文。原任务与补投任务
竞争同一个数据库 pending → processing 原子领取，只有一个能开始模型。已是 processing /
finalizing 的任务不会重放；外部结果未知或进程在模型处理中崩溃仍需独立的安全恢复协议。
本节自动恢复范围是已登记到后台队列且具备当前专用授权的任务，不代表所有旧手动运行均可恢复。

仅手动及夜间窗口外继续按配置间隔检查轻量元数据，清理已删除或移出范围的笔记副本，
不启动正文导出或模型。整根暂停会冻结这类检查，停止/移除同步根则保留副本。源根删除对账
见第 22 节；托管知识库显式删除仍待完成。删除对账不会通过删除在途任务来释放槽位。

PostgreSQL 000166 / SQLite 000070 增加仅覆盖删除待办的索引；唤醒查询分别查每种状态的
第一项，避免用 IN / OR 后排序整个待办。带大量待索引正文的手动或夜间计划不会为了寻找一条
删除反复扫描这些待办。

本阶段 repository、service、database、router、container 完整包回归通过，最后的队列错误
处理专项也通过。隔离 PostgreSQL 16 覆盖 000165–000166 上下迁移、对账、长中文名称及控制
围栏。SQLite 使用 2 万条待索引记录验证删除查询走专用索引，无全表扫描或临时排序；新建及
旧版本升级迁移测试通过。V-Note 69 项相关测试、Web / 移动端类型检查及 Web 构建通过。
这些仍是源码与隔离测试；没有部署或发布，真实 Redis 丢失、VOS 跨版本升级和设备模型验收

## 22. 源根删除与恢复

仍选中且未暂停的根被软删除、彻底删除或移到另一个空间时，源端提供只含当前授权根 ID 的
空元数据范围，不返回新位置的标题或正文。目录版本改变使旧游标重新对账；完整空快照成功
后，目标按已有删除队列清除可见指针，保留空知识库及其原名称、同步记录。仅手动或夜间窗口
外也处理这类无需模型的对账。已经缺失、且从未创建过知识库的根不会新建一个空壳。

根仍缺失时不启动新正文导出或模型，真实 worker 在开始前也检查缺失状态。删除不会绕过
在途模型的安全边界；该篇结果未知时仍保留槽位，并可能延后副本清理。暂停冻结对账，停止或
取消选择则保留已有副本；这些明确的保留操作不会被空范围对账覆盖。

从回收站恢复同一个仍选中的根后，重新核验主体、独占个人空间、根范围和目录版本，再按
当前计划补齐笔记；不要求重新复制凭据。已清除可见指针的笔记可能需要重新索引。恢复与旧的
空快照竞争时，源端目录围栏使旧请求失败，不能清掉新缓存或误报一次成功空遍历。

本阶段没有新增迁移；源端相关测试目前 71 项通过，并覆盖跨空间不泄漏及删除/恢复竞争。
目标 service 完整包回归及源端 Web / 移动端类型检查、Web 构建均通过。
真实 VOS 升级、设备模型验收、单篇/子树暂停、托管知识库删除和物理索引回收仍待完成。
