# HybRAG 算力节点设计

0.1.87 预检版已在 tc207 和 tc35 验证远端 DocReader、解析入库、带引用问答、顺序和权重路由，以及节点不可用时的回退与恢复。业务 Trace 也确认，扫描 PDF 由 tc35 渲染为页面图片后，OCR 和图片描述仍由 tc207 调用知识库的视觉模型完成。

下一版将「算力节点」从共享 DocReader 扩展到共享**文档处理**，同一节点完成解析及所需的 OCR 和图片描述。后续再接入可独立选择的问答、向量化和重排能力。

## 接入与授权

两台机器都完整安装 HybRAG，继续使用现有 VOS 安装流程和 PGV 依赖。提供方管理员在「系统设置 → 算力节点」开启共享并生成一次性接入码，使用方添加一次节点即可。沿用应用在 VOS HTTPS 网关上的鉴权入口，VOS 平台源码的改动不在本次范围内。

已有配对和 DocReader 权限继续有效。提供方主动授权「文档处理」等新增能力后，使用方刷新节点即可看到并按需启用，无需重新配对。节点显示已授权能力及其可用状态。启用远端文档处理后，只有纳入对应路由组的节点可以接收文件，本机加入组后才参与兜底。

接入码携带 VOS 地址和证书指纹，有效期 10 分钟且仅可兑换一次。提供端只保留长期凭据的摘要。关闭共享会暂停远端调用，撤销配对授权后需重新配对。 [现有 DocReader 使用及 API](api/docreader-routing.md)

## 文档处理流程

1. tc207 接收上传、保存原文件并创建处理任务。根据有效解析设置、文件类型、所需能力和节点可用性筛选候选节点。只共享 DocReader 的节点继续用于原有的解析路由。
2. 按顺序或权重为一份文件的一次处理尝试选择节点。tc35 对有文字层的 PDF 提取正文，对扫描页渲染并做 OCR，对需要描述的图片调用视觉模型。视觉模型由 tc35 通过自己的 V-Scheduler 或兼容模型服务调用。tc207 管理员在「算力节点」启用文档处理即可，无需为各知识库填写 tc35 的模型地址。
3. tc35 返回正文、图片及其字节、OCR 文本、图片描述、页码和引用定位，以及各步骤的状态。tc207 负责分块、持久化文件和结果、更新索引及任务状态。两端各自维护业务数据，任务调用无需共享数据库、Redis 或业务文件目录。
4. Trace 分别显示文档解析、OCR、图片描述和入库的执行节点与结果。按有效设置或文件内容跳过某步骤时记录原因。对扫描页启用 OCR 后，识别失败应明确记录，避免把只有图片的结果当作文字识别成功。

### 路由与故障处理

- **按顺序**为默认策略。每次解析从组内第一个可用且支持该文件的节点开始。跳过不可用节点，恢复后按原顺序接收新任务。
- **按权重轮询**按文件数量分配，节点权重默认为 `1`。两台节点权重为 `1:1` 时轮流接单，`3:1` 时每四次调度约分配三次和一次。不可用节点暂时退出候选，新任务按其余节点权重分配，恢复后重新参与。
- 发送前发现节点不可用，可尝试下一候选。发送后固定执行节点，执行失败或状态不明时结束本次尝试并显示原因，允许发起新的重试。文件损坏等输入错误直接返回。
- 远端返回结果后，由 tc207 校验并提交。重新解析时保留原文件和已有可用索引，直到新结果和索引可用。重复返回或已被新尝试取代的结果不应覆盖当前状态或重复入库。

### 对接协议

HybRAG 的共享网关沿用配对凭据鉴权。启用「文档处理」的提供方通过节点检查声明该能力。处理请求携带 PDF、解析参数和本次识别设置。响应流先返回正文及页码定位，再逐图返回图片字节与识别结果。主节点应在响应流成功结束后才接受整次结果。响应流中途报错时，已返回的内容不能用于替换现有索引。

## 文档处理验收

验收继续使用同一局域网内的 tc207 和 tc35。

1. 沿用已有配对。tc35 授权「文档处理」后，tc207 刷新节点并启用该能力。核对授权前后可见能力和原有 DocReader 路由。
2. 在 tc207 上传有文字层的 PDF，确认 tc35 提取正文，tc207 完成入库，并能检索到正文及原始引用位置。
3. 上传扫描 PDF，确认 tc35 返回页面图片、OCR 文本和所需的图片描述，tc207 能检索 OCR 文字。Trace 能区分 tc35 的各项处理与 tc207 的入库。
4. 核对顺序、权重分配，以及节点不可用时的回退和恢复。模拟关键步骤失败，确认重新解析保留已有索引，界面显示失败原因和重试入口。

0.1.87 预检包已在 tc207 和 tc35 上验证上述链路。文字层 PDF 可检索并保留引用位置。扫描 PDF 的 Trace 显示 tc35 完成解析、OCR 和图片描述，tc207 入库后能检索到扫描页文字并定位到第 1 页。临时暂停 tc35 的文档处理后，远端独占路由下的重新解析报错，原分块和检索仍可用。加入本机后验证了回退和恢复。另以 4 份 PDF 分别验证了权重 1:1 和 3:1，实际分配为 2:2 和 3:1。

## 分阶段实现

| 阶段 | 方案与验收 |
| --- | --- |
| DocReader（已验收） | 完整安装、配对、远端解析入库、顺序和权重路由，以及节点故障回退和恢复。 |
| 文档处理（0.1.87 预检已验收） | 复用配对发现并启用新增能力，同一节点执行文档解析和所需的 OCR、图片描述并回传执行端实测耗时，主节点入库。 |
| 文本推理（0.1.87 预检） | 提供方按模型开放文本推理，使用方点击「检查」发现授权模型，逐知识库为自动问题生成和文档摘要选择算力节点，支持 `429 WAIT_COMPUTE_RESOURCE` 限次退避重试、显式配置兜底与重试去重，Trace 显示各阶段执行节点与失败原因。 |
| 对话问答、重排与向量化（后续） | 后续再扩展对话问答、重排和向量化。已有知识库切换向量化节点前，需先验证模型、维度和向量结果兼容。 |
| 按文档条件路由（后续） | 按文件类型、大小、解析引擎匹配路由组。未命中时使用默认组。参考第一条命中规则和能力适配 `fit`。 |
| 按负载分流（后续） | 等节点可以提供及时的队列长度、可用并发和分类型解析耗时后，再参考 `usage`、`fast` 设计动态排序。指标失效时使用组内静态策略。 |

Magpie 将组内分配策略和请求匹配规则分开。HybRAG 沿用这一结构，按文件能力和任务状态定义选择边界。 [Magpie 路由组与规则](https://usemagpie.ai/docs/zh/start#routing)
